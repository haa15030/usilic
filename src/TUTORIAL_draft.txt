  1.　概要

    control+g (control キーと g キーを同時押下) で TUTORIAL の目次画面へ戻り、次に以 下
    のキーでカーソルを移動し return キーを押せば内容を参照できます。

      control+p：カーソルを１行上へ
      control+n：カーソルを１行下へ

    また ';'、':' キーでそれぞれ一つ上、下の章に移動します。これらはマクロキーなので主な
    用法は後述マクロキーを参照してください。

    1.1.　表記

    　キー

    　　　　　^H：controlを押しながら"h"
    　　　　^J^H：^J の後 ^H⁠    
    　　　　^J b：^J の後 'b'⁠   
     　　　^X^Ke：^X の後 ^K の後 'e'⁠   
    　　　　　^M：return⁠        
    　　　　　^[：esc⁠   
    　　　　　^I：tab⁠   
     　　　　　␣：space
     
    　用語

    　　　　　""：キーアサイン以外の文字入力
    　　　　　./：カレントディレクトリ（操作上は . でも可）
     　　　　../：親ディレクトリ（同じく ..）
     　　　　 ~/：ホームディレクトリ（"echo $HOME"^M で表示）⁠   
    　　[モード]：当該モード名⁠  
     　usilic(1)：usilicコマンド自体
    　　usilicrc：各種設定（^I で同ファイル選択後 "e" で編集可）
    　　　　「」：usilic(1)が出力するメッセージ⁠ 
     　　　　PID：プロセスID
            file：ディレクトリおよび特殊デバイス以外のファイル
     　　　SHELL：仮想端末
    　　　suffix：拡張子⁠        
     　mode line：ステータス表示（画面最下行）⁠  

  2.　起動

    usilic(1) は下記のいずれかのモードで動作します。起動後は ^I（SHELL では ^J^I）で表示
    される INFO 画面の「Startup mode:」で確認できます。

    2.1.　Pager

      file 引数 ("usilic file"^M) または引数無しの標準入力経由 ("usilic < file"^M 等) で
      起動した場合、usilic(1) は pager として動作します。
      複数の file 引数起動の場合は、";"/":" でそれぞれ前/後の file へ移ります。
      Pager 起動では画面最下行に下記のようなステータス行（以下 mode-line）が表示されま
      す。

        /Users/usilic/.usilic/usilicrc 00030/00062 48% 1918 usilic-1.5b
        (1)　　　　　　　　　　　　　　(2)　　　　 (3) (4)　(5)

        (1)：モード名
        (2)：カレント行 / 総行
        (3)：カレントページ / 総ページ * (4)：表示サイズ
        (5)：バージョン表示

    2.2.　File Manager

      標準入力も引数も無い起動では、前回終了時 usilic.1 を閲覧していた場合、mode-line は
      下記のようになります。

        usilic.1 01/66 43% 2000 (groff) /Users/usilic/.usilic/
        (1)　　　(2)　 (3) (4)　(5)　　 (6)

        (1)：モード名
        (2)：カレント行 / 総行
        (3)：カレントページ / 総ページ * 100
        (4)：表示サイズ
        (5)：プログラム名
        (6)：以前のモード

      以前のモード名は mode-line(6) に表示され、^G でそこへ移動します。

        /Users/usilic/.usilic/ 01/66 43% 2000 (ls) usilic-1.5b
        (1)　　　　　　　　　　(2)　 (3) (4)　(5)　(6)

      (1)の末尾が「/」かつ(6)が非反転表示の「usilic-1.5b」の場合（以下 (ls)）、^G の連打
      で以前のディレクトリと行き来します。

      2.2.1.　ディレクトリ移動

        (ls) で行頭が「d」(「drwxr-xr-x ...」等) かつ行末が「/」で終わっている行はディレ
        クトリです。 ^M を押すとそこへ移動し、「.」を選択 または ^Xd"."^M（後述 [DIR]）
        とすると、カレントディレクトリ表示内容が更新されます

        ^J^K：カレントディレクトリへ移動⁠        
              カレントディレクトリの (ls) へ移動します。再度 ^J^K とすると「./」を選択し
              た場合同様、表示内容が更新されます。

        ^O^K：親ディレクトリへ移動⁠      
              ^J^K と同じくファイル閲覧中あるいは SHELL 稼働中であっても親ディレクトリへ
              移動します。

         ^JN：N番目のディレクトリへ移動⁠ 
              文字列表示上先頭の「/」（スラッシュ）を 0 からカウント後、N 番目の「/」に
              相当するディレクトリへ移動します。たとえば

                /Users/usilic/.usilic/data/

              での ^J2 は下記へ、

                /Users/usilic/

              ^J2の代わりに ^O^K とした時は親ディレクトリ

                /Users/usilic/.usilic/

              へ移動し、画面最下行 mode-line 上での入力の場合、文字列の先頭がスラッシュ
              の時は、対応するディレクトリへ移ります。たとえば ^Xf"~/.usilic/usilicrc"^M
              （後述 [FILE]）で usilicrc を参照後 ^X^F とタイプした後、

                /Users/usilic/.usilic/usilicrc

              のカーソル行で ^J2 とすると

                ~/Users/usilic/

              へ移動します。
 
      2.2.2.　ファイル表示

          ^M：ファイル内容を表示
              行頭が「-」(「-rxwr-xr-x ...」等) の行は file（通常ファイル）です。^M で
              ファイルの内容が画面に表示され、file の suffix が usilicrc の FILE に設定
              されている場合、指定のプログラムが実行されます（ .gz ファイルを zcat(1) で
              表示等）。
              ファイルサイズが usilicrc の BUFFER で指定した値を超えた場合は、読み込みを
              中止して「Not enough buffer」のメッセージが表示されます (.rpm パッケージの
              内容一覧については、バッファへの読み込みを行わずに pipe(2) を介して表示)。

        ^O^M：ファイルを１行ずつ読み込む
              このキーで file を選択した時は、行単位入力で表示分まで読み込みます。これら
              のモードでは、同じメモリ領域を使用するので、どれかのモードになると他の内容
              は消えます。アクセス履歴にも残りません。

        ^[^M：制御コードをそのまま可視化
              0x7f および 0x20 未満の制御コードを、反転表示 (0x0d の場合は反転の「M」)で
              表示します。アクセス履歴にも残らず usilicrc の FILE 設定も適用されません。
              いずれも ^G および ^J^J で、それぞれ (ls) および以前の file へ戻ります。

        ^J^J：以前の file へ戻る
              (ls) での ^G と同じく、一つ前の file とで行き来します。

      2.2.3.　ファイル操作

           .：現在行選択/非選択トグル
           [：現在行選択ののち下の行へ
           ]：現在行選択ののち上の行へ
         ^Jy：全行選択
         ^Jn：全行解除
         ^Ou：閲覧 [USILIC]
         ^Oc：複写 [CP]
         ^Om：移動 [MV]
         ^Or：削除 [RM]
         ^Jp：実行 [PROGRAM]
        ^J^P：一覧 [PROGRAM]

        (ls)では、 file を複数選択すると、アンダーラインが付加されて閲覧/複写/移動/削除/
        実行の対象となります。

        閲覧
          ^Ou ではそれらが順に画面表示され、; および：キーでファイルを移動します。

        複写/移動
          ^Oc/^Om を押すと文字列入力を促すプロンプトが表示されます。それぞれ複写先/移動
          先の指定を行い、処理後のファイルにはアンダーラインが付加されています。処理先の
          入力時、^M のみ（指定無し）の場合は ~/.usilic/data/ へ複写/移動します。

        削除
          ^Or のプロンプトでは削除の可否を指定してください。対象ファイルを削除する場合は
          「y/n」に "y"^M で削除を実行します。

        実行
          ^Jp では usilicrc の PROGRAM に設定されていない program は SHELL で実行されま
          す。エディター等端末設定が変わってしまうアプリを起動してしまった場合は ^O^S で
           SHELL が再起動します。ただし usilic は例外で、^Ou と同じ動作になります。
          ^J^P の時は、今まで PROGRAM および SHELL で実行したプログラム一覧が表示され、
          さらに ^R で直近以前の実行履歴が表示されます。

      2.2.4.　アーカイブ内容閲覧および展開 [ARC] ⁠       

        下記の suffix を持つファイルを選択すると、(ls) 同様、どれかを選んで内容を閲覧す
        るかまたは .[] キーで複数選択後、^Oa により展開先を指定すればそこへ展開されま
        す。指定無しの ^M のみの場合 ~/.usilic/data/ が展開先となる点は CP/MV と同じで
        す。ただし (ls) で複数のファイルが選択されている場合、ARC は起動できません。

        .tar .tar.gz .tgz .tar.bz2 .tbz2 .tar.xz .txz .tar.zst .tzst .lzh .zip .7z .rpm 
        .deb

  3.　モード

    usilic(1) は新しいモードを起動する前に、現在の mode-line をスタックに積んだうえで表
    示を更新します(^G キーでは最後に積まれた表示に戻ります)。
    これらのスタックの内容は (ls) でディレクトリを指定するか、または ^J2 等でディレクト
    リを移動するとクリアされ、mode-line(6) の位置に「usilic v1.5b」の文字列を表示しま
    す。
    LOCATE、DU 等の一覧表示画面でディレクトリを選ぶと (ls) 画面になりますが、そこでさら
    にディレクトリを選んだ時も上記スタックがクリアされます。

    3.1.　アクセス履歴 [HISTORY]

    　^R：履歴一覧を表示

      FILE、DIR、MAN、LOCATE、FGREP、EGREP、CUT の各モードで ^R キーを押した場合は、入力
      順に保存された文字列で HISTORY リストを表示します。
      PROGRAM および SHELL から入力された文字列は PROGRAM リストに保存され、^R で実行履
      歴一覧が表示されます。

      行おうとしている処理がパーミッションに違反している場合は、ファイル指定できません (
      例えば一般ユーザーが、所有者の異なる読み出し専用のファイルを削除しようとした場合な
      ど)。またファイル指定後、処理が正常終了しなかった場合は、「Exited abnormally」の
      メッセージを表示します。

      , または . キーでカレント行にマーク後、前または次の行に移動します。また < または >
       で特定のファイルを選択できます。例えば DU 画面上で、末尾が「~」のファイル名 (通常
      はバックアップファイル) だけを削除したい場合、RM を起動し EGREP で "~$" を検索後 ^
      M でバッファ内の末尾が「~」の最初の行へカーソルを移動すれば、あとは > キーで該当行
      を選択できます。

      なお以上の機能は SHELL プロンプトで他のプログラムが動作中の時は機能しません。

    3.2.　文字列検索 [FGREP][EGREP]

         ^S：逐次検索
       ^J^S：拡張正規表現で検索

      検索でマッチした文字列はハイライト表示され、^N/^P で次/前のマッチ文字列へ移動。逐
      次検索では文字が入力されるたびにリテラルな検索が行われ、return で確定します。
      主な拡張正規表現におけるメタ文字（特殊文字）を挙げると次のようになります。

      位置・境界
         ^：行の先頭（例: ^A は行頭のAにマッチ）
         $：行の末尾（例: Z$ は行末のZにマッチ）
        \b：単語の境界（例: \bcat\b は「cat」単独にマッチし、「concatenate」にはマッチし
            ない）
        \B：単語の境界以外

      任意の文字・文字の集合（文字クラス）
            .：改行を除く任意の1文字
          [ ]：括弧内のいずれか1文字（例: [abc] は a, b, c のどれか1文字）
         [^ ]：括弧内の文字以外の1文字（例: [^0-9] は数字以外の1文字）
        [a-z]：範囲指定（例: [a-z] は小文字アルファベット、[0-9] は数字）
           \d：任意の数字（[0-9] と同じ）
           \D：数字以外の任意の文字（[^0-9] と同じ）
           \w：英数字とアンダースコア（[a-zA-Z0-9_] とほぼ同じ）
           \W：英数字とアンダースコア以外
           \s：任意の空白文字（スペース、タブ、改行など）
           \S：空白文字以外の任意の文字

      繰り返しの回数を表す（量指定子）
            *：0回以上の繰り返し（なくても良いし、いくつあっても良い）
            +：1回以上の繰り返し（最低1回は必要）
            ?：0回または1回だけ存在（あってもなくても良い）
          (n)：ちょうどn回の繰り返し（例: \d(4) は数字4桁）
         (n,)：n回以上の繰り返し
        (n,m)：n回以上、m回以下の繰り返し
        *?/+?：非強欲マッチ（最短一致）（通常は一番長くマッチしようとする性質を、一番短
               くマッチするように変える）

      グループ化と条件分岐（OR）
            |：OR（または）（例: cat|dog は「cat」または「dog」）
          ( )：グループ化。文字列を1つの単位としてまとめ、後から再利用（キャプチャ）でき
               るようにする
        (?: )：非キャプチャグループ（グループ化はするが、後から再利用しない。処理を高速
               化したいとき用）

      先読み・後読み（アサーション）
        (?=...) ：肯定先読み（直後に...が続く位置にマッチ）
        (?!...) ：否定先読み（直後に...が続かない位置にマッチ）
        (?<=...)：肯定後読み（直前に...がある位置にマッチ）
        (?<!...)：否定後読み（直前に...がない位置にマッチ）

      エスケープ処理（\）について
        \.：ドット文字そのものを検索
        \?：質問マークそのものを探したい

      基本正規表現では一部のメタ文字を\（バックスラッシュ）でエスケープする必要がありま
      す。
               ¥+：1回以上の繰り返し
               ¥?：存在するかしないか
        ¥( ... ¥)：複数の文字を一つにまとめる
          ¥(n,m¥)：n回からm回の繰り返し

    3.3. バッファ/ファイル分割 [CUT]

    　 ^Jc：指定文字列でバッファを分割
    　^J^C：指定文字列でファイルを分割⁠  

      検索文字列を入力すると、データが読み込まれているバッファに対して拡張正規表現による
      検索を行い、マッチした文字列を含む行でバッファ内容を分割したうえで当該行の目次一覧
      を作成します。
      ^J^C ではファイル自身を表示上分割し、マッチした文字列行の目次一覧を作成したのち分
      割後の内容データをバッファに読み込みます。後述 [FILE] によるアクセス履歴一覧では「
      ファイル名 "文字列"」で表示され、^J^J キーでは、判別のため目次リスト表示の画面へ戻
      ります。

    3.4.　ディスク使用量 [DU]

    　^Jd：ディスク使用量をdu(1)で集計
     ^J^D：集計結果画面へ戻る⁠   

      ^Jd で DU モードを起動した場合、カレントディレクトリを対象に du(1) を実行します。^
      G で集計中断後は、既存の集計結果へ移動します。
      ^J^D の場合も既存リストにアクセスするだけなので、カレントディレクトリ変更してもリ
      ストは更新されません。

    3.5.　ファイル位置検索 [LOCATE]

    　^Jl：<u>locate(1)</u>用データベースを作成
     ^J^L：LOCATE画面へ戻る

      データベース作成中に^Gを押すと、途中まで作成済みのデータベースへ移動します。mode-l
      ine のプロンプトで、例えば ".tgz"^M とすれば、システムに含まれる .tgz という suffi
      x を持つ全ファイル名を表示します。^J^Lでは既存のデータベースで検索を行い、^Jlの時
      はデータベースの更新を行います。

    3.6.　マニュアルページ閲覧 [MAN]

    　^Jm：マニュアルページを表示
     ^J^M：閲覧履歴一覧を表示
 
      入力文字列が既存のページにマッチした場合、man(1)により当該マニュアルを表示します。
      ^J^M では履歴一覧から選択するか、または新たに入力された文字列に該当するマニュアル
      ページを表示します。

    3.7.　プログラム実行 [PROGRAM]

    　^Jp：プログラム名を入力
     ^J^P：閲覧履歴一覧から選択

      usilic(1) を一旦抜けて、program リスト (usilicrc で設定) から選択した program を実
      行します。^Jp キーで mode-line 行から新規に入力された program 名が、リストに載って
      いない場合は、後述の SHELL に画面を切り替えて、そこで実行します。^J^P では今まで実
      行したプログラム名のソート一覧を表示します。

    3.8.　ファイル [FILE]

    　^Jf：ファイル名を入力
     ^J^F：閲覧履歴一覧から選択

      mode-line 行で入力、または今までにアクセスしたリストから選択したファイルを表示しま
      す。FILE のファイルリストでは、使用したプログラムがあれば、 file 名に「(プログラム
      名)」を付加して、また CUT で使用された文字列はダブルクォート (") で括って表示しま
      す。ただし File-selector で ^O^M または ^[^M で選択したファイルは ^J^J キーや FILE
       リストでは表示されません。

    3.9.　ディレクトリ [DIR]

    　^Jd：ディレクトリ名を入力
     ^J^D：閲覧履歴一覧から選択

      mode-line 行で入力、または今までにアクセスしたリストから選択したディレクトリに移動
      します。^G でリストへ戻りますが、^J^K、^J2 等ディレクトリ移動キーを入力すると DIR 
      モードからは離脱します。 

    3.10.　文字列コピー [COPY]

     　^@：範囲指定開始/終了トグル。
      ^X␣：矩形範囲指定開始/終了トグル
      ^[w：指定範囲をクリップボードへコピー。

      mode-line 以外の文字列をクリップボードへコピーします。^@ で範囲指定を開始した後
      は、カーソル移動後のハイライト表示がコピー対象エリアとなります。一旦 ^@ で範囲指定
      を解除したあとも、再度 ^@ により複数のエリアが作成され、同様の切り替えは ^X␣（矩形
      範囲指定）でも機能します。
      作成された全エリアは ^[w でクリップボードへコピーされ、^O^Y でペースト可能です。た
      だしクリップボードでは、ユニバーサル設定がデフォルトで有効になっているため、他のア
      プリへもペースト可能である一方、同時使用の iCloude 環境があればそちらへも反映され
      てしまいます。予期せぬ文字列がペーストされる事態を回避したければ、「システム設定」
      ⇒「一般」⇒「AirDropとHandoff」」⇒「ユニバーサルクリップボード」で設定を無効にして
      ください。

    3.11.　ファイル編集 [EDIT]

     　e：環境変数 $EDITOR で編集

      ファイル名 (mode-line(1)) が file で、プログラム名 (mode-line(5)) が空白の時は usi
      licrc に定義されているエディターを起動します。
      カレント行番号 N を +N オプションでエディターへ渡して起動するので、同オプションが
      使用できるエディターを設定しておくと便利です。デフォルトでは vi(1) に設定してあり
      ます。

    3.12.　usilic(1) 情報 [INFO]

    　 ^I：主な情報を表示
     ^J^I：SHELL から発動

      usilic(1) に関する下記の情報を表示します。

      Boot options：起動オプション
      Startup file：設定ファイル
          TUTORIAL：チュートリアルで使用
             ERROR：稼働中のエラーメッセージ
             SHELL：仮想端末からの出力
              DATA：~/.uslic/data/の (ls)
              WORK：作業ファイル
⁠        
      ERROR と SHELL については、usilicrc の KEY 設定を検証するためのキーアサインをその
      まま残してあります。それぞれ ^X^Ke、^X^Ks となっていますが、ついでに DATA へのアク
      セスとして ^X^Kd を割り当てました。

    3.13.　仮想端末 [SHELL]

      ^[s：SHELLへ移動
      ^Xs：SHELLを再起動
      ^J.：カレントディレクトリへ移動
      ^J,：カレントディレクトリ一覧
      ^Jw：バッファ名表示
     ^J^W：バッファの内容表示

      ^J. で SHELL プロンプトのカレントディレクトリを (ls) の位置に設定します（^J, では 
      ls(1) を実行）。
      異常動作およびプログラム実行中によりプロンプトが戻っていない場合、CP や PROGRAM 等
       SHELL プロンプトを使用する機能および EXIT を実行しようとすると「SHELL busy」の
      メッセージと共に SHELL 画面に切り替わります。
      SHELL 以外のモードにいる時に SHELL プロンプトが戻った時は「Exit」と表示され、任意
      のキーで消えます。
      SHELL プロンプトでパイプ（"usilic < file"^M）または file 引数（"usilic file"^M）で
       usilic(1) を起動した場合は、それぞれファイル名「(stdin)」、「file」で内容を表示
      し、directory 引数（"usilic directory"^M）ではカレントディレクトリの (ls) になりま
      す。また上記の "man bash"^M 後の出力は、一時的な PAGER 環境変数により usilic(1) へ
      のパイプ入力へ切り替わるため「(stdin)」で表示されます。この機能では、モード切り替
      えで使用する socket(2) の認証に shell のプロセス ID を使用しているので SHELL プロ
      ンプトで su(1) 等を実行した場合、そのプロンプトからはモードが切り替わりません。(No
      te の章の socket(2) 参照)
      usilic(1)の SHELL は CP/MV/RM 等のファイル操作を行うためだけに用意した仮想端末なの
      で最小限の機能しかなく、エディタやページャ等、端末設定を操作するプログラムは正常に
      動作しません。ただしプログラム名が program リストに載っている場合は、PROGRAM に画
      面を切り替えて実行されます。そうでないプログラムを意図せず起動してしまった時は、
      キー入力で終了可能なら終了を、それ以外のケースでは ^Xs により SHELL を再起動してく
      ださい。

    3.14　補完

      SHELLプロンプトの直後に ^I を押すと実行可能なファイルリストを表示します。これは環
      境変数 $PATH が示すディレクトリ下に配置された実行可能ファイル一覧です。どれかを選
      択するか、または入力された文字列にマッチする名称のプログラムが $PATH 上に存在する
      場合はカーソル位置に挿入され、複数の候補があればビープ音で通知します。さらに ^I で
      今度はそれらのリストが表示され、同じ手順によりプログラムの絞り込みが可能です。そう
      して確定したプログラム名に続き ␣ のあとの ^I ではカレントディレクトリの内容一覧が
      表示されるので引数の特定にも同じ手順を使用でき、^Jp（PROGRAM）および ^Jm（MAN）の
      プロンプトでも ^I による実行ファイル名補完は機能します。
      FILE および DIR では、$PATH 上の実行ファイル検索は行いません。カレントディレクトリ
      内の file およびディレクトリだけが補完の対象になります。

    3.15.　コマンド行

      行頭が「usilic v1.5b:」（一時的な PS1 環境変数）のプロンプトでは下記のキーが使用で
      きます。

      ^H：カーソル位置から左へ１文字削除
      ^K：カーソル位置から表示行末まで削除
      ^U：カーソル位置から表示行頭まで削除
      ^Y：カーソル位置に削除内容を挿入
      ^D：カーソル位置の文字削除
      ^E：表示行末へ移動
      ^A：表示行頭へ移動
      ^B：左へ１文字移動
      ^F：右へ１文字移動
      ^L：画面を再表示
      ^Q：機能キャラクタ入力
      ^W：^J^W、^Jw のコマンドを再表示(SHELL)
      ^W：以前のディレクトリ名を表示(CP/MV)
      ^I：ファイル名補完
      ^C：入力を中断

    3.16.　EXIT

    　^X^C
    　^[^[ 

      usilic(1) をディレクトリ引数で起動した場合、各モードを発動する際、前回終了時のカー
      ソル位置等の情報を ~/.usilic/history から読み取って同じ状態を復元します。モード終
      了時も次回発動のために同ファイルへ状態が保存され、usilic(1) 自体を起動する際も、標
      準入力無しかつ引数無しの時は、前回終了時の状態を復元します。
      それらのすべての履歴は単一の file  ~/.usilic/history を介してやり取りするため複数
      の usilic(1) を同じ引数で起動しようとすると、今稼働中の usilic(1) を kill(1) した
      上で起動し直します。
      SHELL の章の「SHELL busy」のメッセージが表示された時は、^X^C または ^[^[ キーで EX
      IT を再実行して下さい。

  4.　設定

    usilic(1) は起動時に ~/.usilic/usilicrc を読み込んで環境設定を行います。同ファイルが
    存在しなければ、~/.local/lib/usilic/ から usilicrc を ~/.usilic/ へコピーしたうえで
    内容を読み込みます。

    以下は usilicrc で定義されている内容です。

    ARCHIVE
      書式：suffix0　 suffix1
      用例：.tar.gz　 .tgz
      内容：

      suffix0 を持つアーカイブファイルの内容を、下記の suffix1 (ソースファイルの str.c 
      で定義) の設定で表示。

      suffix1　 program　 (option)
      .tar　　　tar　　　 tvf
      .tgz　　　gzip　　　-dc | tar tvf -
      .tar.bz2　bzip2　　 -dc | tar tvf -
      .lzh　　　lha
      .zip　　　unzip　　 -l
      .rpm　　　rpm　　　 -qplv
      .deb　　　ar　　　　tv

    FILE
      書式：suffix program (option)
      用例：.gz　　gzip　　-dc
      内容：

      program を実行して suffix を持つファイルの内容を平文表示。

    PROGRAM
      書式：suffix program (option)
      用例：.html　lynx
      内容：

      suffix を持つファイル引数で program を実行。

    EDITOR
      書式：editor
      用例：vi
      内容：

      EDIT で起動されるエディター。

    BUFFER
      書式：size
      用例：2
      内容：

      file に割り当てるバッファ size (MB)。

    CODE
      書式：code0 code1
      用例：1　　 8　　 ...
      内容：

      ここでの設定以外の 0x20 未満の機能キャラクタが、上記の suffix を持たない file に含
      まれていて、ファイルの漢字コード (Note の章の 漢字コード 参照) が jis でない場合に
      は、バイナリファイルとみなして file(1) を実行し、該当コードとファイルタイプを表
      示。

    SHELL
      書式：shell
      用例：tcsh
      内容：

      shell で SHELL モードを起動。("SHELL" 環境変数に使用されている値が "bash" および "
      tcsh" 以外の場合は、この設定 (bash(1) または tcsh(1) を指定可能) が必要)

    HISTORY
      書式：line
      用例：500
      内容：

      HISTORY リストへ保存する最大 line。(mode-line [2] の値が line に等しくなった後は、
      一番古い行から削除)
 
    WAIT
      書式：wait
      用例：10
      内容：

      組み込みまたはキーボードマクロキーを wait (10 msec) 間隔で実行。

    LS
      書式：flag
      用例：1
      内容：

      ls(1) 表示モード (起動後は ^Ol で切替) の設定用フラグ。(セットされている時は、ファ
      イル名のみ表示)

    SCROLL
      書式：flag
      用例：1
      内容：

      スクロールモード (起動後は ^Oh で切替) の設定用フラグ。(セットされている時は、最下
      行より上の範囲でスクロール)

    CP
      書式：cp (option)
      用例：cp -rvi
      内容：

      CP モードの cp(1) 起動オプション。(デフォルト: cp -rvf)

    MV
      書式：mv (option)
      用例：mv -vi
      内容：

      MV モードの mv(1) 起動オプション。(デフォルト: mv -vf)

    RM
      書式：rm (option)
      用例：rm -rvi
      内容：

      RM モードの rm(1) 起動オプション。(デフォルト: rm -rvf)

    KEY
      内容：

      KEY で表示されるキーのカスタマイズ。

  5.　補足

  環境
    usilic は最初に起動する際 ~/.usilic/ および /tmp/.usilic/ (ソースファイルの config.s
    h で定義) の作業ディレクトリを作成します。
    usilic(1) は今の端末が SHELL かどうかを判別するのに "USILIC" 環境変数を使用していま
    す。特にこの変数が定義されている端末では usilic(1) はfile manager で起動できません。

    pager で使用する場合は、端末で一旦 "export PAGER=usilic"^M としておけば dvi2tty(1) 
    や man(1) の出力を usilic(1) で参照できます。ただし SHELL では、この "PAGER" 環境変
    数の値は変更できません。

  漢字コード
    sjis (shift-jis) または 7bit-jis の漢字コードを含むファイルは、内容をバッファに読み
    込んだ後 euc (内部コード) に変換します。それに伴い、mode-line [4] (表示サイズ) が実
    際のファイルサイズとは異なって表示される事があります。

    バッファ内 (内部コード変換前) の漢字コードの判別は、バッファの先頭から行い jis につ
    いては、コードを検出した時点で終了しますが euc および sjis では、バッファの末尾まで
    チェックした後、多く含まれている方のコードで判別します。

    ^O^M でファイル表示した場合や usilic(1) を pager で起動した時は、入力行毎に、判別お
    よびコード変換を行いますが、行内に１バイト半角カナが多用されている場合や、quote 系
    フォーマットで継続行を含むファイルでは、正常に判別できない場合があります。

    ^[M でベタ表示した場合、内部コードの変換も行わないので例えば ^X^W で ~/.usilic/data/
     へ保存したバッファの内容に、元のファイルの漢字コードを反映させたい場合 (例えば sjis
     コードを含む差分ファイルなど) に使用できます。

  プロセス間通信
    socket(2)
    SHELL の章の shell プロンプトで、プログラムの出力を usilic(1) へリダイレクトした場
    合、その usilic(1) (shell の子プロセス) は shell のプロセス ID を含むファイル名の so
    cket(2) を作成して、自分にリダイレクトされた内容を、そこへ書き込みます。一方 shell 
    を起動した usilic(1) (shell の親プロセス) が、その socket(2) を見つけた場合、上記の
    リダイレクト内容を、ファイル名「(stdin)」で、その socket(2) から読み込みます。shell 
    のプロンプトから file 引数で usilic(1) を起動した場合は、socket(2) の代わりに同じ名
    前の file を使用します。

    pipe(2)
    上記の socket(2) の使用以外では、 file の内容をバッファへ読み込む際に fork(2) した子
    プロセスとの間で、pipe(2) によるプロセス間通信を使用しています。
