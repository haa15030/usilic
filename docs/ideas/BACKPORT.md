# 旧C実装(old/)への機能移植: 規模の見積もりと進め方

2026-09-21、ユーザー依頼(「GUI関連を除く現時点での全ての機能を旧へ反映するとしたらどれくらいの
規模か。旧ソースにコメントを入れて、新ソースのどこに該当するかが分かるように。C++学習のための
プロジェクトでもある。コーディング形式は問わない」)に対する調査結果。

**注意**: 以下は粗い見積もりである。CHANGES.mdの見出し・キーワードとgitログ(件名)による
仕分けであり、差分そのものは読んでいない。機能ごとの精密な見積もりは、この文書の「進め方」
1(機能差の一覧化)を終えた時点でやり直す。

## 1. 規模の実測

| | 全体の行数 | コード行(コメント・空行を除く) |
|---|---|---|
| 旧C(`old/src`、17ファイル) | 17,227 | 約15,900(関数 382) |
| C++版(GUIを除く`src`+`app`) | 42,711 | 約16,300(クラス41) |
| C++のテスト | 26,176 | 約17,600 |

- コード行はほぼ同じ。C++版は行数の約6割がコメント。
- 旧Cはコメントが約5%(関数382個に対し、コメントの入った行は約700)。
- ただし機能量は同じではない。C++版はSTL(`string`/`vector`/`map`)で行数が縮む分、旧Cより
  機能が多い。旧Cへ移すと1機能あたりの行数は2〜3倍になると見ている。

## 2. 旧版と異なる機能(GUIを除く)

CHANGES.mdの約250項目(モード関連)を「旧版の移植」と「ユーザー要望による新規・変更」に粗く
分けると、後者が約3割(約80項目)。gitログはC++関連が717コミット、うち新設・追加・実装が約160。

- **キー体系の再編**: `^X`プレフィックスの廃止→`^O`/`^J`へ移行。新設は`^J^U`、`^Ju`、`^[u`、
  `^Ou`、`^J0〜9`など。
- **履歴と`^R`の再設計**: カテゴリ別リング、USILIC履歴、`^J^P`。
- **GREP**: その場ハイライト、インクリメンタルサーチ(`^S`)、`grep -F/-E`化。
- **一覧の戻り値・注釈**: DIR/FILE/MAN/DU/LOCATE/USILIC/CUTの統一、モードラインの再設計。
- **アーカイブ**: rar/7z/xz/zst/lzh、入れ子、`tvf`表示。
- **LOCATE**: `updatedb`、`^C`中断、長い行の中央省略。
- **PROGRAM**: 選択中ファイルの自動挿入、Quick Look。
- **COPY/PASTE**: 矩形選択、行番号ジャンプ。
- **SHELL**: 引き渡し、PAGER、Tab補完など約30項目。
- **プロセス**: 単一起動時の乗っ取り、SIGTERM/SIGHUP、非同期読み込み+`^G`中断。
- **表示**: タブの内部表現(U+2060)、禁則処理、UTF-8の幅表、ANSI属性の解釈。
- **文書**: TUTORIAL、HELPの全面改稿。

## 3. 移植の規模(見積もり)

機能のまとまりを30〜40個と見て、大きさ別にざっくり試算する。

| 大きさ | 1つあたり(Cの新規・変更行) | 個数の目安 |
|---|---|---|
| 小(局所的) | 約100行 | 12 |
| 中 | 約500行 | 12〜15 |
| 大(横断的。キー再編・モードライン・履歴など) | 約1,500行 | 6〜8 |

合計で約1.2万〜2.5万行の新規・変更。旧ソース全体(約1.6万行)の1〜1.5倍に相当する。旧Cは
グローバル変数が多くテストも無いため、横断的な機能は単純な追加にならず既存コードの改造を伴う。

## 4. 進め方

1. **機能差の一覧を作る**(最初の一歩): 上の粗い分類を、機能ごとに「旧にある/ない/挙動が違う」
   まで詰める。作業は小さく、その後の見積もりの精度が上がる。
2. **差分テストで進める**: 旧版(`/usr/local/bin/U`)とPTYハーネス(および本物のTerminal.app上の
   中継)で、同じ操作を旧版とC++版に流して画面を比較する。テストの無い旧Cの安全網になる。
3. **フェーズ分割**: 小さくて独立したもの→中規模→横断的なもの(キー再編は最後)の順。各段階で
   旧版として動く状態を保つ。
4. **コメントと対応表**: 旧ソースの各関数の頭に日本語の説明と`[C++]`対応先(クラス名・関数名、
   行番号は書かない)を入れ、`docs/legacy-cpp-map.md`に対応表を置く。参照先が実在するかを
   確かめるスクリプトも用意する。関数382個ぶんで、機能移植とは独立して先に進められる。

## 5. 判断が要ること

- **キー再編**: 旧Cのキー割り当てまでC++版に合わせて変えるか、旧の割り当てを保って新機能だけ足すか。
  前者は旧版としての互換性が変わる。
- **対象外の範囲**: GUIに加えて、macOS専用(Quick Lookなど)も対象外にするか。
- **優先順位**: 学習用として、コメント付けと対応表を先に進める案(見積もりが小さく、C++の理解に
  すぐ役立つ)を推奨。
