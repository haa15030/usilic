usilic (C++版) ビルド手順

  • 必要なもの(共通)
  • macOS
  • Linux (Ubuntu/Debian系)
  • FreeBSD(2026-11-05、16.0-CURRENT・RTX 3050でインストールから通しで確認)
  • Windows(WSL2)
  • Windows(Git Bash / MSYS2)
  • Windows(ネイティブ、MinGW-w64)
  • Docker(.devcontainer/)
  • macOS: Finderからアイコンクリックで起動する(.appバンドル)
  • ソースを手元で変更する(公開時の方針、2026-11-01)
  • ビルドターゲット早見表

src/cpp/以下のC++移植版usilicを、何も入っていないまっさらなmacOS/Linuxマシンから実際にビルドできるようになるまでの手順。

「なぜこれが要るのか」を各所に書いてあるのは、パッケージの過不足で無反応/謎のリンクエラーになったときに原因を追いやすくするため(2026-08-24、Intel Mac実機でのSDL2_ttfリンクエラー[docs/CHANGES.md項目419]の調査を機に整備)。

ブランチに注意(2026-10-05追記): git cloneで取り出されるのは既定のブランチmaster (2026-08-29の版)で、それ以後の作業はmpi-gui-fixブランチにある(まだmasterへマージしていない)。cloneした後、ビルドの前に必ず

git checkout mpi-gui-fix
git pull

とする(git branchで今のブランチを確かめられる)。2026-10-05、WSL2でmasterのままビルドしたため古い版(^Hが効かず^TがTUTORIAL)を試していた、という実例があった。

必要なもの(共通)

  • C++17対応コンパイラ(clang++またはg++)とmake
  • git
  • ncursesのヘッダ/ライブラリ(terminal_display.cppがsetupterm/tputs/tgoto等のterminfo APIを使用)
  • pkg-config
  • SDL2とSDL2_ttfのヘッダ/ライブラリ

SDL2/SDL2_ttfは本来GUIモード(-g、GraphicalDisplay)専用のはずだが、src/cpp/Makefileはsrc/以下の.cppをmake usilic/ make testどちらでも無条件に全部ビルドする作りで、graphical_display.cpp自身も<SDL2/SDL.h>/<SDL2/SDL_ttf.h>を#ifdef無しで無条件includeしている。つまりCUIしか使わない場合でも、コンパイルを通すためだけにSDL2/SDL2_ttfのヘッダ/ライブラリが必須になる(GUIウィンドウを一度も開かない場合でも)。

macOS

  1. Xcode Command Line Tools(clang++/make/git、およびncursesのヘッダ/ライブラリもSDKに同梱): 
    xcode-select --install

    入っている場合も、更新があれば入れる(Label:の後の名前を-iに渡す。下は2026-11-06のBig Surの例):

    softwareupdate --list
    sudo softwareupdate -i "Command Line Tools for Xcode-13.2"

    古いまま使うと、コンパイラ(clang)より新しいSDKが既定になっていることがあり、make usilicがmac_cursor.mmの中で止まる(下の「Command Line ToolsのclangとSDKの版の不一致」)。

  2. Homebrew(未導入の場合): 
    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    Intel Macでは、Homebrewは新しく入れられない(2026-11-06、インストーラがHomebrew on macOS is only supported on Apple Silicon processors!で止まる)。前から入っているHomebrewは今も使える。入っていなければ、代わりにMacPortsを使う。そのMacのmacOSの版に合う.pkgを入れたら、ターミナルを開き直す(/opt/local/binをPATHに足す~/.zprofileは、開いたままのウィンドウには反映されない)。

  3. pkg-config(pkgconfパッケージが提供)、SDL2、SDL2_ttf: 
    brew install pkgconf sdl2 sdl2_ttf

    MacPortsの場合:

    sudo port selfupdate
sudo port install pkgconfig libsdl2 libsdl2_ttf
  4. 公開鍵の登録(リポジトリが非公開の間だけ必要)。鍵を作り(プロンプトに戻るまではEnterのみ)、公開鍵の1行をクリップボードへ入れる: 
    ssh-keygen -t ed25519
pbcopy < ~/.ssh/id_ed25519.pub

    ブラウザでhttps://github.com/settings/keysを開いてGitHubにサインインし、New SSH keyのKeyに貼って登録する(Titleは任意、Key typeはそのまま)。登録できたか確かめる(初回はyes、Hi ...! と出ればよい):

    ssh -T git@github.com
  5. クローンしてビルド(make usilicでbuild/usilicができ、make testで単体テスト一式(doctest)を実行する): 
    mkdir -p ~/git
cd ~/git
git clone -b mpi-gui-fix git@github.com:haa15030/usilic.git
cd usilic/src/cpp
make usilic
make test

    ※macOSのzshは、打ち込んだ行の#を注釈として扱わない(interactivecommentsが既定で無効)。注釈付きの行を貼るとzsh: no matches found等になるので、このファイルの枠には注釈を書かない。

  6. (任意)/usr/local/bin/Uとしてインストール(INSTALL_NAMEがusilicではなくUなのは、src/install.shが入れる旧C版/usr/local/bin/usilicと衝突しないよう、日常的に試すための短い専用名としてユーザー自身が選んだもの): 
    sudo make install

Command Line ToolsのclangとSDKの版の不一致

Big Sur(mpr、2026-11-06)で、make usilicが次のエラーで止まった:

NSBundle.h:91:143: error: function does not return NSString

clangは12.0.5(Xcode 12.5の世代、合うSDKは11.3)なのに、既定のSDK(xcrun --show-sdk-path)はMacOSX12.1.sdkだった。古いclangが12.1のSDKのNS_FORMAT_ARGUMENTを読めない。usilicのソースの問題ではない。上の手順1.でCommand Line Toolsを更新すれば版が揃う。更新できない時は、ls /Library/Developer/CommandLineTools/SDKs/でclangに合う版のSDKを探して指定する:

SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX11.3.sdk make usilic

Intel Mac(Sequoia)固有の注意点

Xcode 15以降のデフォルトリンカ(通称ld-prime)が、Homebrew製の一部dylib構成(sdl2_ttfがsdl2ではなくsdl2-compatを参照する構成など)で「ライブラリもリンクコマンドも正しいのにシンボルが見つからない」という既知の非互換を起こすことがある(docs/CHANGES.md項目419で実際に発生・特定)。対策としてMakefileのDarwin向けLDLIBSに-Wl,-ld_classic(旧リンカの強制指定)を組み込み済みなので、上記の手順通りにmakeすれば追加の対応は不要。万一同種のリンクエラーが再発した場合は、pkg-config --cflags --libs sdl2 SDL2_ttfの出力・file/ lipo -infoでのアーキテクチャ・nm -gUでのシンボルの実エクスポート状況、の3点を順に確認するとよい(docs/CHANGES.md項目419の調査ログに実例あり)。

Apple Silicon + Homebrewが/opt/homebrewの場合

/opt/homebrew/libはデフォルトのリンカ検索パスに含まれないが、pkg-config経由でSDL2/SDL2_ttfの-I/-Lは自動的に解決されるため、追加のCFLAGS/LDFLAGS指定は不要(2026-07-16に検証済み、CLAUDE.mdの経緯記録も参照)。

4. sudoとキーボード

echo '%wheel ALL=(ALL:ALL) ALL' > /usr/local/etc/sudoers.d/wheel
chmod 440 /usr/local/etc/sudoers.d/wheel
mkdir -p /usr/local/etc/X11/xorg.conf.d
cat > /usr/local/etc/X11/xorg.conf.d/keyboard.conf <<'EOF'
Section "InputClass"
Identifier "keyboard"
MatchIsKeyboard "on"
Option "XkbModel" "jp106"
Option "XkbLayout" "jp"
Option "XkbOptions" "ctrl:swapcaps"
EndSection
EOF

※XkbOptionsの行はCaps LockとCtrlを入れ替える設定。要らなければ省く。

5. 日本語入力に対応したSDL2

パッケージのSDL2はfcitxに対応していないので、-gで日本語を入力できるようportsからビルドする。時間と数GBの空きが要る。

git clone --depth 1 https://git.FreeBSD.org/ports.git /usr/ports
echo 'devel_sdl20_SET+=DBUS FCITX' >> /etc/make.conf
cd /usr/ports/devel/sdl20
make install-missing-packages
make BATCH=yes reinstall clean

pkg query '%Ok=%Ov' sdl2 | grep -E 'DBUS|FCITX'(DBUS=on、FCITX=on と出ることを確かめる)

pkg lock -y sdl2

※ロックすると pkg upgrade でパッケージ版に戻らない。sdl2を更新する時は pkg unlock -y sdl2 で解除し、この節の cd 以降をやり直す。

注意点

以下は上の表記の区別とは別で、` はコマンドやファイル名を表す。

インストールとパッケージ

  • pkg installのfirefoxの最後に長いメッセージ(boost・gcc14・libjxl・firefoxの未対応機能等)が出るが、対応が要るものは無い。
  • python3はEPUBのリンクのEpub(narou2epub)・Pdf(url2pdf)に要る。そのほかの準備はHELPのnarou2epub・url2pdfの所。
  • 最初の起動のインストールの案内で入らなかったものは、次の起動でもう一度だけ実行し、その後はモードラインに「見つかりません」と出すだけなので、手で入れる。
  • suはwheelグループのユーザーだけ。インストーラで入れなかったユーザーはpw groupmod wheel -m ユーザー名。
  • noto-jpは-cの表示に要る(無いと端末で豆腐になる字がある)。入れた後はログインし直す。

GPUと画面

  • 再起動の前にkldloadが何も言わずに戻ればカーネルと合っている(AMD・Intelはコンソールの文字が細かくなる)。CURRENTで失敗するならportsからビルドする(インストーラのDistribution Selectでsrcを入れておく)。drm系はユーザーをvideoグループに入れる。
  • ログインできずlogin:のままなら、/var/log/lightdm/x-0.logと/var/log/Xorg.0.logを見る。keyboard.confの書き間違いや、kld_listの設定漏れでXが起動しない(2026-11-05に実際に両方)。
  • NVIDIAでウィンドウの合成表示が有効だと、xfwm4がglXBindTexImageEXTで止まり、画面が固まることがある(RTX 3050・ドライバ595.112.07、2026-11-05。引き金は未特定)。マウスカーソルだけ動く状態になったら、sshからpkill -9 xfwm4で戻る。合成表示を切るxfconf-queryはsshからでは届かないので、XfceのTerminalで実行する。
  • 端末に重ねる-gはmacOSだけ(Linux・FreeBSDは重ねない、ユーザー判断2026-10-31)。

日本語入力とSDL2

  • パッケージのSDL2はDBUS・FCITXがoffで、-gでは窓は開いても日本語が入らない(pkg query '%Ok=%Ov' sdl2で分かる)。ビルドしてもoffのままなら、古い設定が残っているのでmake rmconfigとmake cleanをしてからやり直す。
  • ビルドの前にpkg lockしているとmake reinstallが止まる。pkg unlock -y sdl2で解除する。

日本語とキーボード

  • Xfceのメニュー等を日本語にするLANGは~/.xprofileに書く(lightdmの/usr/local/etc/lightdm/Xsessionが読む、2026-11-01に確認)。~/.login_confやログインクラスで設定するとコンソール(vt)のログインまで日本語になり、vtのフォントに漢字が無いので化ける。
  • keyboard.confを使わずXfceだけで設定するなら、設定→キーボード→レイアウトで「システムのデフォルトを使用」を外し、モデルをJapanese 106-key、レイアウトの追加で▶を開かずに親のJapaneseの行を選ぶ(▶の下のKana・Macintosh・OADG 109A・Dvorakは標準以外の変種。Kanaを選ぶと[が]になる等、2026-11-01に実際にはまった)。ただし、これだとログイン画面はjp106にならない。
  • Caps LockをCtrlにするだけならXkbOptionsをctrl:nocapsにする。すぐ試すならXfceの端末でsetxkbmap -model jp106 -layout jp -option ctrl:swapcaps(戻すのはsetxkbmap -option)。Xfceのレイアウトで「システムのデフォルトを使用」を外していると、ログインの時にXfceが上書きしてXkbOptionsが消えることがあるので、keyboard.confを使うならXfce側はデフォルトのまま。
  • コンソール(vt)はXとは別で、sysrc keymap=jp.capsctrl.kbdして再起動(16.0-CURRENTの/usr/share/vt/keymaps/にjp.kbdと並んであることを2026-11-01に確認。名前のとおりCaps LockをCtrlにするもので、入れ替えではない)。

公開鍵とPATH

  • https://のURLでcloneすると鍵は使われず、非公開の間はトークンを聞かれる(公開後はhttps://github.com/haa15030/usilic.gitでよく、7の鍵の登録も要らない)。トークンの作り方は下の「ソースを手元で変更する」の4。
  • GUIを入れない時は、別のマシンのブラウザで鍵を登録する。Macならssh ユーザー名@<IP> cat .ssh/id_ed25519.pub | pbcopyで1行がクリップボードに入る(FreeBSDのsshdが動いていなければ、rootでsysrc sshd_enable=YES; service sshd start)。GUIがあってもsshで作業中なら、鍵の作成・表示はsshで済み、登録もMacのブラウザでできる。

Windows(WSL2)

  2. パッケージ(Ubuntuの中で): 
    sudo apt-get update
sudo apt-get install -y build-essential libncurses-dev pkg-config \
    libsdl2-dev libsdl2-ttf-dev git fonts-noto-cjk unzip

    fonts-noto-cjkは-gの日本語の表示用、unzipはEPUBと.zip(ARC)用(WSLのUbuntuには最初は入っていない。どちらも無ければ最初の起動時の案内にも出る)。-gの和文のゴシック体は、Windows側のメイリオ(/mnt/c/Windows/Fonts/meiryo.ttc)があればそれを使う(無ければNoto Sans CJK)。^Ofのフォント一覧にも/mnt/c/Windows/Fontsのフォントが出る。

  3. ビルドとインストール: リポジトリは非公開なので、gh auth login(GitHub CLI、sudo apt-get install gh)かSSHの鍵を用意してからgit cloneし、 
    cd usilic
git checkout mpi-gui-fix   # 冒頭の「ブランチに注意」参照
cd src/cpp
make usilic
make install          # ~/.local/bin/usilic、~/.local/lib/usilic/

    ~/.local/binがPATHに無ければ~/.profileにexport PATH="$HOME/.local/bin:$PATH"を足す。リポジトリはWSLの中(~/の下)に置く。/mnt/c/...(Windows側のドライブ)の下はファイルの読み書きが遅く、パーミッションも正しく扱えない。

  4. -g(GUI): WSLg(Windows 11、またはWindows 10の新しい版のWSL)があればusilic -gでWindowsのデスクトップにウィンドウが出る(X/Waylandの設定は要らない)。
  5. Windows側とのつながり(usilicがWSLの中かを実行時に判定する、src/cpp/src/platform.hpp):
    • 動画・url2pdfで作ったPDF・EPUBのWebのリンク(Open)は、explorer.exeでWindowsの既定のアプリ(ブラウザ・動画プレーヤー等)で開く。WSLの中のファイルはwslpath -wで\\wsl.localhost\Ubuntu\...の形にして渡す。
    • COPY(^[w/^[p)とEPUBのWebのリンクのCopyは、clip.exeでWindowsのクリップボードへ入る(日本語はUTF-16に変換して渡す)。
    • Windows側のファイルは/mnt/c/Users/<名前>/...で見える。

Windows(Git Bash / MSYS2)

2026-10-05追加(.steering/20261005-windows-gitbash/)。Git Bashの土台はMSYS2(Cygwin系)の実行環境なので、MSYS2でビルドしたusilic.exeがGit Bashでも動く見込み。Git for Windowsにはコンパイラが無いので、ビルドはMSYS2で行う。-g(GUI)は使えない(MSYS2のMSYS環境にSDL2が無いため。SDL2が見つからないとMakefileが自動でNO_GUI=1になり、src/graphical_display_stub.cppでビルドする)。LOCATEも使えない(locate/updatedbが無い)。

  1. MSYS2を入れる: https://www.msys2.org/ のインストーラでC:\msys64へ。スタートメニューの「MSYS2 MSYS」の端末を開く(「MINGW64」「UCRT64」ではない。それらはWindowsネイティブのexeを作る環境で、usilicが使うforkや擬似端末が無い)。
  2. パッケージ(MSYS2 MSYSの端末で): 
    pacman -Syu                     # 初回は端末を閉じて開き直し、もう一度
pacman -S --needed gcc make ncurses-devel pkgconf git unzip
  3. ビルド: 
    git clone ...(WSL2の節と同じく、非公開なので認証を用意する)
cd usilic
git checkout mpi-gui-fix   # 冒頭の「ブランチに注意」参照
cd src/cpp
make usilic                     # build/usilic.exe
  4. MSYS2の端末で使う: make install(~/.local/bin/usilic、MSYS2のホームはC:\msys64\home\<名前>)。~/.bashrcにexport PATH="$HOME/.local/bin:$PATH"。
  5. Git Bashで使う: Git BashのホームはC:\Users\<名前>(MSYS2からは/c/Users/<名前>)なので、 
    make install PREFIX=/c/Users/<名前>/.local

    で入れ、Git Bashの~/.bashrcにexport PATH="$HOME/.local/bin:$PATH"。libstdc++/libgccは静的にリンクしてある。それ以外に足りないDLLがあれば、MSYS2の端末でldd build/usilic.exeを見て、/usr/bin/msys-*.dllのうちGit Bashの/usr/binに無いもの(例えばmsys-ncursesw6.dll)を/c/Users/<名前>/.local/bin/へコピーする。msys-2.0.dllはGit Bashのものを使う(コピーしない)。版の違いで動かなければ、4.のMSYS2の端末で使う。

  6. Windows側とのつながり(src/cpp/src/platform.hppのisMsys()): 動画・url2pdfのPDF・EPUBのWebのリンク(Open)はexplorer.exeでWindowsの既定のアプリで開き(パスはcygpath -w)、COPYとEPUBのリンクのCopyは/dev/clipboardでWindowsのクリップボードへ入る。
  7. 最初の起動時の案内: MSYS2の端末(pacmanがある)では、groff・texinfo・p7zipのうち無いものをpacman -S --neededで入れるコマンドを置く。Git Bashでは案内しない。
  8. 文字の大きさ: Git BashもMSYS2の端末もmintty。usilic側ではなく端末で変える。その場ではCtrl++/-(Ctrl+ホイール、Ctrl+0で戻す。閉じると元に戻る)。ずっと変えるには、ウィンドウを右クリック→Options→Text→Fontで選んでSave (~/.minttyrcにFontHeight=14のように入る)。Git Bash(C:\Users\<名前>)とMSYS2(C:\msys64\home\<名前>)はホームが別なので、それぞれで設定する。

Windows(ネイティブ、MinGW-w64)

2026-10-15追加(.steering/20261015-windows-native-gui/)。POSIXの互換層(MSYS2のmsys-2.0.dll)を使わない、Windowsのふつうの実行ファイルで、2つある(2026-11-02、.steering/20261102-windows-console-cui/)。usilic.exeはSDLの窓(-g、アイコンから起動してもコンソールの窓が出ない)、usilic-c.exeはコマンドプロンプト・PowerShell・Windows Terminalの中のCUI(-gで窓も開ける)。CUIはWindows 10 1809以降(VT処理)、SHELLはConPTY。親子のusilicの受け渡し(KEYの子から親のキー実行等)は使えない。(ls)の一覧はWindowsにlsが無いので、usilicの中でls -alFと同じ形の行を作る(src/cpp/src/native_ls.cpp)。外部コマンドはCreateProcessWで起動する(src/cpp/src/child_process_win.cpp)。ファイル名はマニフェストのactiveCodePageでUTF-8にしているので、Windows 10 1903以降が要る。

Macからクロスビルドする

  1. ツール: brew install mingw-w64。
  2. SDL2・SDL2_ttf: GitHubのlibsdl-orgのリリースからSDL2-devel-<版>-mingw.tar.gz・SDL2_ttf-devel-<版>-mingw.tar.gzを落とし、中のx86_64-w64-mingw32/のinclude・lib・binを~/.local/mingw/へコピーする(別の場所ならmakeにWIN_SDL_DIR=...)。
  3. ビルド: 
    cd src/cpp
make WINDOWS=1 -j8 usilic     # build-win/usilic.exe・usilic-c.exe(設定はwindows.mk)
make WINDOWS=1 dist           # build-win/usilic/ と build-win/usilic-win64.zip

    distは、strip済みのusilic.exe・usilic-c.exe・SDL2.dll・SDL2_ttf.dllと、lib/usilic/(usilicrc・HELP・HELP.notes、~/.local/lib/usilic/HELP.epubがあればそれも)をまとめる。

Windowsで使う

  1. usilic-win64.zipを好きな所(例えばC:\Users\<名前>\usilic\)に展開する。
  2. usilic.exeをダブルクリックするか、コマンドプロンプトからusilic.exe [ディレクトリ|ファイル]。引数が無ければカレントディレクトリ(ダブルクリックならexeの場所)の(ls)。端末の中で使うならusilic-c.exe (usilic.exe -cはそれを案内して終わる)。^Zのサスペンド、CUIの^J^F等の-g専用の機能は使えない。
  3. 設定・履歴は%USERPROFILE%\.usilic\(HOMEが無ければUSERPROFILEを使う)、HELP・既定のusilicrcはexeの隣のlib\usilic\。フォントはC:\Windows\FontsのMSゴシック(無ければConsolas)、和文のゴシック体はメイリオ、明朝体は游明朝。
  4. 窓が出ない時はメッセージボックスで理由を出す(フォントが無い等)。SDL2.dllが無いとWindows自身が起動前に知らせる。

Windows上でビルドする

MSYS2のUCRT64の端末でpacman -S --needed mingw-w64-ucrt-x86_64-gcc make zip、SDL2・SDL2_ttfは上と同じ配布物をWIN_SDL_DIRに置き、make WINDOWS=1 CXX=g++ WINDRES=windres STRIP=strip usilic。

Docker(.devcontainer/)

このリポジトリの.devcontainer/Dockerfile(Ubuntu 26.04ベース)には上記Linux手順のパッケージが最初から含まれている(2026-08-24、libsdl2-dev/libsdl2-ttf-dev/pkg-configを追加[docs/CHANGES.md項目420] -- それ以前はSDL2関連が抜けており、make usilicがヘッダ不足でコンパイルすら通らない状態だった)。実際にdocker buildしたイメージへ、ホストのbind mountを経由せずリポジトリをgit cloneし直した上でmake usilic/make testが成功することを検証済み。

注意(重要): ホストのMac上のリポジトリをこのDockerコンテナへbind mountして使う場合、コンテナ内でmake/make cleanを実行すると、共有されたbuild/ディレクトリにLinux版バイナリが書き込まれ、Mac側のbuild/usilic(Mach-O)を壊す(あるいはrm -rf buildでMac側ごと削除する)。コンテナ内でのビルド確認はリポジトリをコンテナ内の別パス(例: /tmp/usilic)へコピーまたはgit cloneし直した上で行うこと。Mac側で確認済みのバイナリをそのまま使い続けたい場合は、コンテナ内でmake系コマンドを一切実行しないこと。

macOS: Finderからアイコンクリックで起動する(.appバンドル)

cd usilic/src/cpp
make app        # build/usilic.app ができる
open build/usilic.app   # 動作確認(実際にウィンドウが開く)

usilicは引数無し起動だとmacOSでは元々GUIモード(SDL2の独立ウィンドウ、ターミナル不要)がデフォルトになる設計になっているため、make usilicが作るbuild/usilicをそのまま.appバンドルへ包むだけで、Finderからのダブルクリック起動に対応できる(2026-08-24、docs/CHANGES.md項目421)。GUI側の追加実装は不要だった。

build/usilic.appをFinderで/ApplicationsやDockへドラッグすれば、以後は通常のアプリと同じ感覚でアイコンクリック起動できる。ターミナルからのU起動(-cでCUIも選択可)は影響を受けない。

署名について: make appは末尾で.appバンドル全体をad-hoc署名し直す(codesign --force --deep -s -、単体実行ファイル用の署名をバンドル構造にそのまま流用するとspctl -aがrejectedになるため必須)。有償のDeveloper ID証明書による署名・公証(notarization)は行っていないため、他のMacへコピーした場合やcom.apple.quarantine属性が付いた場合は、初回起動時にGatekeeperの確認(右クリック→「開く」)が必要になることがある。ローカルでビルドしたものをそのまま使う分にはこの確認は出ない(quarantine属性が付かないため)。

アイコンは未設定(Finderの汎用実行ファイルアイコンのまま)。.icnsをsrc/cpp/packaging/へ追加しInfo.plistのCFBundleIconFileを設定すれば、以後のmake appで自動的に反映される。

4. 自分の変更をGitHubに置く・作者に送る(ここからアカウントが要る)

やりたいことGitHubのアカウント鍵・認証
公開リポジトリをhttps://でcloneする・更新を取り込む不要不要
自分の変更を自分のGitHubに置く(fork→push)必要SSHの鍵、またはgh auth login
作者に変更を送る(Pull Request)・不具合を報告する(Issue)必要(ブラウザでサインイン)
  • SSHの鍵はアカウントに登録するもので、https://github.com/settings/keysはサインインしないと開けない。
  • 鍵は使うマシンでssh-keygen -t ed25519で作り、~/.ssh/id_ed25519.pubの1行を上のページのNew SSH keyに貼る。そのマシンにまだブラウザが無ければ(FreeBSDを入れた直後等)、sshでつないだ別のマシンの端末でこの1行をコピーし、そちらのブラウザ(サインイン済み)で登録してもよい。
  • gh auth login(GitHub CLI)なら鍵を作らずに済み、表示されたコードを別のマシンのブラウザで入力しても通る。
  • 鍵とURLの組み合わせに注意: SSHの鍵が使われるのはgit@github.com:haa15030/usilic.gitの形のURLだけ。https://github.com/...で非公開のリポジトリをclone(や自分のforkへpush)するとUsername for 'https://github.com':と聞かれ、パスワードの欄にはGitHubのパスワードではなくトークンを入れる(パスワードは受け付けない)。鍵を登録したなら、URLをgit@github.com:の形にすればトークンは要らない(2026-11-01、FreeBSDで鍵を登録した後にhttps://でcloneしてこれに当たった。既にcloneしたものはgit remote set-url origin git@github.com:…で切り替えられる)。
  • トークンの作り方(https://のまま使う場合): GitHubにサインイン→右上のアイコン→Settings→ (左の一番下)Developer settings→Personal access tokens→Fine-grained tokens→Generate new token。Token name(何でもよい)、Expiration(有効期限)、Repository accessはOnly select repositoriesでusilicを選び、Permissions→Repository permissionsのContentsをRead-only(cloneだけ)かRead and write(pushもする)に。Generate tokenで表示されるgithub_pat_…はその時しか表示されないのでコピーしておく。cloneのUsername:に自分のアカウント名、Password:にこのトークンを貼る。毎回聞かれないようにするにはgit config --global credential.helper store(~/.git-credentialsに平文で保存される。気になるならcacheで一定時間だけ覚えさせる)。gh auth loginを済ませておけば、ghがこの役目も引き受ける。
  • 手順: GitHubで作者のリポジトリをFork → git remote add mine git@github.com:<自分>/usilic.git → git push mine my-fix → GitHubのページからPull Request。
  • 作者以外が1つのリポジトリだけを読む機械用には、リポジトリの所有者が登録するDeploy key(Settings→Deploy keys)もある(非公開の間に、作者が自分の別マシンへ取ってくる時等)。
