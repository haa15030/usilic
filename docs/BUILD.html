src/cpp/以下のC++移植版usilicを、何も入っていないまっさらなmacOS/Linuxマシンから実際にビルドできるようになるまでの手順。

「なぜこれが要るのか」を各所に書いてあるのは、パッケージの過不足で無反応/謎のリンクエラーになったときに原因を追いやすくするため(2026-08-24、Intel Mac実機でのSDL2_ttfリンクエラー[docs/CHANGES.md項目419]の調査を機に整備)。

ブランチに注意(2026-10-05追記): git cloneで取り出されるのは既定のブランチmaster (2026-08-29の版)で、それ以後の作業はmpi-gui-fixブランチにある(まだmasterへマージしていない)。cloneした後、ビルドの前に必ず

git checkout mpi-gui-fix
git pull

とする(git branchで今のブランチを確かめられる)。2026-10-05、WSL2でmasterのままビルドしたため古い版(^Hが効かず^TがTUTORIAL)を試していた、という実例があった。

必要なもの(共通)

  • C++17対応コンパイラ(clang++またはg++)とmake
  • git
  • ncursesのヘッダ/ライブラリ(terminal_display.cppがsetupterm/tputs/tgoto等のterminfo APIを使用)
  • pkg-config
  • SDL2とSDL2_ttfのヘッダ/ライブラリ

SDL2/SDL2_ttfは本来GUIモード(-g、GraphicalDisplay)専用のはずだが、src/cpp/Makefileはsrc/以下の.cppをmake usilic/ make testどちらでも無条件に全部ビルドする作りで、graphical_display.cpp自身も<SDL2/SDL.h>/<SDL2/SDL_ttf.h>を#ifdef無しで無条件includeしている。つまりCUIしか使わない場合でも、コンパイルを通すためだけにSDL2/SDL2_ttfのヘッダ/ライブラリが必須になる(GUIウィンドウを一度も開かない場合でも)。

macOS

  1. Xcode Command Line Tools(clang++/make/git、およびncursesのヘッダ/ライブラリもSDKに同梱): 
    xcode-select --install

    入っている場合も、更新があれば入れる(Label:の後の名前を-iに渡す。下は2026-11-06のBig Surの例):

    softwareupdate --list
    sudo softwareupdate -i "Command Line Tools for Xcode-13.2"

    古いまま使うと、コンパイラ(clang)より新しいSDKが既定になっていることがあり、make usilicがmac_cursor.mmの中で止まる(下の「Command Line ToolsのclangとSDKの版の不一致」)。Xcode本体(App Store)も入っていると、make usilicがYou have not agreed to the Xcode and Apple SDKs license.で止まることがある(2026-11-18、Sequoiaのクリーンインストールで)。xcode-select -pがXcode本体(/Applications/Xcode.app/…)を指していて、そのライセンスにまだ同意していない。同意する:

    sudo xcodebuild -license accept

    (Xcode本体を使わないなら、代わりに sudo xcode-select -s /Library/Developer/CommandLineTools でCommand Line Toolsへ切り換えてもよい)

  2. MacPorts(未導入の場合): そのMacのmacOSの版に合う.pkgを入れたら、ターミナルを開き直す(/opt/local/binをPATHに足す~/.zprofileは、開いたままのウィンドウには反映されない)。開き直さずに続けるならsource ~/.zprofile。which portが/opt/local/bin/portを出せばよい(sudo port …がsudo: port: command not foundになるのは、たいていこれ。2026-11-13、Sequoiaのクリーンインストールで)。なお、最初から PATH にある/usr/local/binは macOS の/etc/pathsによるもので、MacPortsとは関係ない。2026-11-07から、macOSの版やCPU(Intel・Apple Silicon)によらずMacPortsに一本化した(ユーザー判断)。Homebrewは古いmacOS(Big Sur等)に対応しておらず、Intel Macには新しく入れられず(2026-11-06、インストーラがHomebrew on macOS is only supported on Apple Silicon processors!で止まる)、2027年9月以降はIntel MacではHomebrew自体が動かなくなる予定(https://docs.brew.sh/Support-Tiers)。使えたり使えなかったりするより、どのMacでも同じ手順にする。最初の起動のインストール(groff等)もMacPortsで行う。
  3. pkg-config、SDL2、SDL2_ttf: 
    sudo port selfupdate
    sudo port install pkgconfig libsdl2 libsdl2_ttf

    既にHomebrewでpkgconf sdl2 sdl2_ttfを入れてあるMacは、そのままでもビルドできる(pkg-configが見つけた方を使う)。

  4. 公開鍵の登録(リポジトリが非公開の間だけ必要)。鍵を作り(プロンプトに戻るまではEnterのみ)、公開鍵の1行をクリップボードへ入れる: 
    ssh-keygen -t ed25519
pbcopy < ~/.ssh/id_ed25519.pub

    ブラウザでhttps://github.com/settings/keysを開いてGitHubにサインインし、New SSH keyのKeyに貼って登録する(Titleは任意、Key typeはそのまま)。登録できたか確かめる(初回はyes、Hi ...! と出ればよい):

    ssh -T git@github.com
  5. クローンしてビルド(make usilicでbuild/usilicができる): 
    mkdir -p ~/git
cd ~/git
git clone -b mpi-gui-fix git@github.com:haa15030/usilic.git
cd usilic/src/cpp
make usilic

    make test(単体テスト一式、doctest)の実行は任意。テスト用のビルドと実行にかなり時間がかかる(テストは1400件近い)。usilicを使うだけなら不要。※macOSのzshは、打ち込んだ行の#を注釈として扱わない(interactivecommentsが既定で無効)。注釈付きの行を貼るとzsh: no matches found等になるので、このファイルの枠には注釈を書かない。

  6. (任意)/usr/local/bin/Uとしてインストール(INSTALL_NAMEがusilicではなくUなのは、src/install.shが入れる旧C版/usr/local/bin/usilicと衝突しないよう、日常的に試すための短い専用名としてユーザー自身が選んだもの): 
    sudo make install

Command Line ToolsのclangとSDKの版の不一致

Big Sur(mpr、2026-11-06)で、make usilicが次のエラーで止まった:

NSBundle.h:91:143: error: function does not return NSString

clangは12.0.5(Xcode 12.5の世代、合うSDKは11.3)なのに、既定のSDK(xcrun --show-sdk-path)はMacOSX12.1.sdkだった。古いclangが12.1のSDKのNS_FORMAT_ARGUMENTを読めない。usilicのソースの問題ではない。上の手順1.でCommand Line Toolsを更新すれば版が揃う。更新できない時は、ls /Library/Developer/CommandLineTools/SDKs/でclangに合う版のSDKを探して指定する:

SDKROOT=/Library/Developer/CommandLineTools/SDKs/MacOSX11.3.sdk make usilic

Intel Mac(Sequoia)固有の注意点

(Homebrewで入れたSDL2を使っていた頃の記録。MacPortsのSDL2でも-ld_classicはそのまま付く。) Xcode 15以降のデフォルトリンカ(通称ld-prime)が、Homebrew製の一部dylib構成(sdl2_ttfがsdl2ではなくsdl2-compatを参照する構成など)で「ライブラリもリンクコマンドも正しいのにシンボルが見つからない」という既知の非互換を起こすことがある(docs/CHANGES.md項目419で実際に発生・特定)。対策としてMakefileのDarwin向けLDLIBSに-Wl,-ld_classic(旧リンカの強制指定)を組み込み済みなので、上記の手順通りにmakeすれば追加の対応は不要。万一同種のリンクエラーが再発した場合は、pkg-config --cflags --libs sdl2 SDL2_ttfの出力・file/ lipo -infoでのアーキテクチャ・nm -gUでのシンボルの実エクスポート状況、の3点を順に確認するとよい(docs/CHANGES.md項目419の調査ログに実例あり)。

6. 日本語入力・音声・usilicの起動

lightdmのログイン画面でログインし、Xfceに入る。

  • アプリケーション -> 設定 -> Fcitx 5 の設定 で、「入力メソッド」にMozcがあることを確かめる(無ければ右の一覧のMozcを左へ移して「適用」。Englishで入れると無かった。スクリプトは~/.config/fcitx5/profileにMozcを入れてある)。「DBusがFcitxと接続できませんでした。Fcitxは動いていますか?」と出たら、Fcitx 5が自動で起動していない。その画面の「Fcitx 5 を実行する」でつながる。次から自動で起動するよう、端末で mkdir -p ~/.config/autostart && cp /usr/share/applications/org.fcitx.Fcitx5.desktop ~/.config/autostart/(スクリプトは済ませてある)。
  • 音声: パネルに音量のアイコンが無ければ、パネルを右クリック -> パネル -> 新しいアイテムの追加 -> 「PulseAudio プラグイン」。出力先(マザーボードの内蔵・HDMI)は、そのアイコンかpavucontrol(アプリケーション -> マルチメディア -> PulseAudio 音量調節)で切り換える。再生中の音もそのまま付いてくる。
  • アプリケーション -> アクセサリー -> usilic で起動する。

BIOS(CSM)でも起動できるようにする(Debianから)

UEFIで入れたDebianに、BIOS用のGRUBを足す。BIOSで起動した時もDebianの起動メニュー(UEFIと同じ/boot/grub/grub.cfg)が出て、そこからUbuntuも選べる。Debianにrootでログインし(sudo -i):

1. 起動メニューにUbuntuが出るようにする(インストーラが他のOSを見つけた時は済んでいる):

grep -n OS_PROBER /etc/default/grub

GRUB_DISABLE_OS_PROBER=falseの行が無ければ:

apt-get install -y os-prober && echo 'GRUB_DISABLE_OS_PROBER=false' >> /etc/default/grub && update-grub

2. SSDの名前を確かめる(以下sdaの例。USBの外付けならTRANがusb):

lsblk -o NAME,SIZE,TRAN,PARTTYPENAME,MOUNTPOINTS

3. GPTのSSDでBIOSのGRUBを起動するには、中身を置く1MBほどの「BIOS boot」区画が要る。区画の一覧でBIOS boot(コードEF02)を探す:

apt-get install -y gdisk grub-pc-bin
sgdisk -p /dev/sda

無ければ、先頭の区画の前の隙間(セクタ34〜2047、どのインストーラも区画を2048から始めるので空いている)に作る:

sgdisk -a 1 -n 0:34:2047 -t 0:ef02 -c 0:biosgrub /dev/sda

4. BIOS用のGRUBをSSDの先頭(MBR)とBIOS boot区画へ書く:

grub-install --target=i386-pc /dev/sda

「Installation finished. No error reported.」と出ればよい。マザーボードの設定でCSMを有効にし(UEFIのブートを無効にできるならそうして)起動を確かめる。

※grub-pc(パッケージ)ではなくgrub-pc-binなのは、grub-pcはUEFIのgrub-efi-amd64と同時に入れられない(入れるとUEFI側が外れる)ため。grub-pc-binはBIOS用のファイルだけで、UEFIの方はそのまま。

※grub-efi-amd64が更新されてもBIOS側は書き直されないので、GRUBの大きな更新の後は4.をもう一度実行しておく(起動メニューのgrub.cfgは共用なので、カーネルの更新だけなら要らない)。

※BIOSで「起動できるディスクが無い」と言われたら、そのマザーボードは保護MBRの起動フラグを見ている: parted /dev/sda disk_set pmbr_boot on。これでUEFIで起動しなくなる機械があるので、その時はoffに戻す。

※他のマシンにつないでUEFIで起動するには、SSDのEFIシステム区画のEFI/BOOT/BOOTX64.EFI(機械に登録の無いディスクを起動する時の決まった場所)が要る。Debianのを置く:

echo 'grub-efi-amd64 grub2/force_efi_extra_removable boolean true' | debconf-set-selections && dpkg-reconfigure -f noninteractive grub-efi-amd64

Ubuntuのスワップファイルを使う(Debianから)

UbuntuはSSDの区画ではなく/swap.img(Ubuntuの/の中のファイル)をスワップにしている。Debianからも、Ubuntuの区画を/mnt/ubuntuへつないで同じファイルを使える(同時に動くことは無いので、2つのOSで共用して困らない。休止状態(ハイバネート)を使わない場合)。Debianのrootで:

1. Ubuntuの区画を探す(ext4で、Debianの/ではない方。LABELか大きさで見分ける):

lsblk -o NAME,SIZE,FSTYPE,UUID,MOUNTPOINTS

2. /etc/fstabへ足す(UUIDは1.のUbuntuの区画の値。nofailは、Ubuntuの区画が無くてもDebianの起動を止めないため):

mkdir -p /mnt/ubuntu
echo 'UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /mnt/ubuntu ext4 defaults,nofail 0 2' >> /etc/fstab
echo '/mnt/ubuntu/swap.img none swap sw,nofail 0 0' >> /etc/fstab

3. つないで有効にする(次からは起動の時に自動で):

systemctl daemon-reload && mount /mnt/ubuntu && swapon -a && swapon --show

※Debianにもスワップの区画を作ったなら、swapon --showに両方が出る(両方使われる)。区画を外すなら、/etc/fstabのswapの区画の行を消す。

※Ubuntuの/swap.imgの大きさはUbuntuのインストーラが決める(swapon --showのSIZE)。逆にUbuntuからDebianのスワップの区画を使うこともでき、その時はUbuntuの/etc/fstabへUUID=(スワップの区画) none swap sw,nofail 0 0を足し、/swap.imgの行を消してファイルも消す。

注意点(Linux)

  • 音声: 音声のサーバーはPipeWire(pipewire-pulseがPulseAudioの役)。マザーボードの内蔵もHDMIもALSAの装置として自動で並び、mpv・mplayerは何も設定しなくてもそこへ出す。FreeBSDのようなhw.snd.default_unitやアプリごとの設定、audioグループは要らない(systemd-logindがログインした人に権限を渡す)。
  • HDMIが出力先に出ない: 音源のカードの構成が「アナログ出力」だけになっている。pavucontrolの「設定」タブで、そのカードの構成を「Digital Stereo (HDMI) Output」等にする。NVIDIA・AMDのGPUのHDMIは、マザーボードの音源とは別のカードとして並ぶ。
  • NVIDIAとセキュアブート: UEFIのセキュアブートが有効だと、DKMSでビルドしたNVIDIAのモジュールは署名を登録(MOK)するまで読み込まれない。インストールの途中か再起動の時に青い「Perform MOK management」の画面が出たら、「Enroll MOK」を選び、インストールの時に決めたパスワードを入れる。分からなければ、UEFIの設定でセキュアブートを切る。
  • インストーラをEnglishで進めた時(BIOSで起動したDebianのテキストのインストーラは「Language:」に日本語が無い。日本語の文字を出せない画面のため。起動メニューの Graphical install なら日本語を選べる): メニューやusilicのHELPが英語になるのは、システムの言語(/etc/default/locale)がen_US.UTF-8のままだから。rootで update-locale LANG=ja_JP.UTF-8 して、ログインし直す(スクリプトは済ませてある)。時刻は timedatectl set-timezone Asia/Tokyo。既にFcitx 5を一度起動していたら、Mozcは6.のとおり手で足す。
  • Ubuntuでホスト名(mpi等)が引けない: Debianは/etc/resolv.confにDHCPのドメイン(domain …)が入り、ssh mpi・scp … mpi:がルーターのDNSでmpi.ドメインとして引ける。UbuntuのServer版はsystemd-networkdがDHCPのドメインを使わない設定なので(/etc/resolv.confがnameserver 127.0.0.53とsearch .)、IPアドレスを打つしかなかった。スクリプトは/etc/systemd/networkd.conf.d/usilic.confに[DHCPv4]のUseDomains=yesを置く(再起動の後でresolvectl domainにドメインが出る)。手でするなら同じファイルを作って再起動。
  • 小説のEPUB(narou2epub)で「ensurepip is not available」: Debian・Ubuntuは、Pythonのvenvにpython3-venvが要る(スクリプトは入れてある)。手で sudo apt-get install python3-venv した後は、そのままもう一度実行すればよい(作りかけのvenvは作り直す)。
  • Ubuntuのfirefox: aptのfirefoxはsnapを入れる中継ぎのパッケージ。minimizedでsnapdが無い時は apt-get install -y snapd してから。

  • suはwheelグループのユーザーだけ。インストーラで入れなかったユーザーはpw groupmod wheel -m ユーザー名。
  • noto-jpは-cの表示に要る(無いと端末で豆腐になる字がある)。入れた後はログインし直す。

GPUと画面

  • 再起動の前にkldloadが何も言わずに戻ればカーネルと合っている(AMDはコンソールの文字が細かくなる。Intelはi5-7500では変わらなかった)。CURRENTで失敗するならportsからビルドする(3.の※、インストーラのDistribution Selectでsrcを入れておく)。2026-11-07、i5-7500ではpkgのdrm-612-kmodが1600030向け、カーネルが1600029で読み込めず、Xが/dev/dri/card0を開けずにCannot run in framebuffer modeで止まり、login:のままだった。
  • このカーネルとドライバの版のずれは、GPUの種類によらない(AMDのamdgpuもIntelのi915kmsも同じdrm-kmodのパッケージで、ファームウェアのgpu-firmware-*-kmod、NVIDIAのnvidia-driverもカーネルのモジュール)。インストールした日のスナップショットとpkgの組み合わせで決まるので、RX580で一度動いても、別の日のスナップショットで入れ直した時や、カーネルはそのままでpkg upgradeした後の再起動で起きうる。3.の※のビルドの後でpkg lockしておけば、pkg upgradeでのずれは避けられる(ビルドしていなくても、動いているうちにpkg lock -y drm-612-kmodしておいてよい)。NVIDIAはpkg lock -y nvidia-driver。カーネルのモジュールが別のパッケージ(nvidia-kmod等、pkg info -d nvidia-driverで分かる)なら一緒にロックする(ドライバ本体とモジュールの版が違うと動かないので、片方だけにしない)。drm系はユーザーをvideoグループに入れる。
  • ログインできずlogin:のままなら、/var/log/lightdm/x-0.logと/var/log/Xorg.0.logを見る。keyboard.confの書き間違いや、kld_listの設定漏れでXが起動しない(2026-11-05に実際に両方)。
  • NVIDIAでウィンドウの合成表示が有効だと、xfwm4がglXBindTexImageEXTで止まり、画面が固まることがある(RTX 3050・ドライバ595.112.07、2026-11-05。引き金は未特定)。マウスカーソルだけ動く状態になったら、sshからpkill -9 xfwm4で戻る。合成表示を切るxfconf-queryはsshからでは届かないので、XfceのTerminalで実行する。
  • 端末に重ねる-gはmacOSだけ(Linux・FreeBSDは重ねない、ユーザー判断2026-10-31)。
  • IntelのiGPU(i5-4570SのHaswell、2026-11-13)では、GTK4のアプリ(pavucontrol等)を開くと固まり、kill -9 でも止まらず(ps でRのままCPU99%)、dmesg にlkpi_vmf_insert_pfn_prot_locked: page rename failed: page is mappedが並ぶ。GTK4がGPUで描く所でdrm-kmod(linuxkpi)の不具合を踏んでいる(procstat -kk PID でvm_fault→lkpi_vmf_insert_pfn_prot_locked)。そのプロセスは再起動しないと消えない。~/.xprofileにexport GSK_RENDERER=cairoを書いてGPUを使わずに描かせる(スクリプトは--gpu=intelの時に書く)。固まったpavucontrolが残っていると、次からは「Failed to register: タイムアウトしました」で開かない(同時に1つしか起動しない作りのため)。
  • mpvの「ioctl(I915_GEM_USERPTR) failed. Try running as root but expect poor stability.」は、IntelのiGPUで映像をGPUで描く時の警告で、映像は出る(rootで動かす必要は無い)。固まるようなら mpv --vo=x11(~/.config/mpv/mpv.confにvo=x11)。

別のマシンへディスクを付け替えた時(2026-11-13)

  • RTX 3050のマシンで入れたディスクをi5-4570S(IntelのiGPU)に付けたら、Xfceが出ずLANもつながらなかった。スクリプトを--gpu=…で実行し直せば、前のGPUのモジュールをkld_listから外し、NVIDIAの/etc/X11/xorg.confを/etc/X11/xorg.conf.nvidiaへよけ、新しいGPUのドライバを入れる(NVIDIAのマシンへ戻す時は、xorg.conf.nvidiaをxorg.confへ戻して--gpu=nvidia)。ただし、スクリプトはネットワークが要るので、先に下のLANを直す。
  • LAN: インストーラは/etc/rc.confにifconfig_rge0="DHCP"のようにインターフェースの名前で書く。別のマシン(Intelのem0等、ifconfig -l で分かる)ではそれが効かず、つながらない。rootで sysrc ifconfig_DEFAULT="DHCP"(名前ごとの設定の無いインターフェースもDHCPにする、スクリプトも書く)。その場で直すなら dhclient em0。IPアドレスが来ても外へ出られない(ping 8.8.8.8 がNo route to host)時は、netstat -rn -f inet | grep default にルーターが無い。route add default ルーターのアドレス で当座をしのぎ、再起動の後も無ければ sysrc defaultrouter="ルーターのアドレス"。DNSだけ引ける(host は答える)のは、ルーター自身がDNSで、同じLANの中ならデフォルトルートが無くても届くから。

音声(2026-11-08)

  • mpvの出力にCan't open audio device /dev/dsp: Permission deniedと出たら、ユーザーがaudioグループに入っていない。16-CURRENTでは/dev/dsp*・/dev/mixer*がroot:audioの0660(ls -l /dev/dsp*)で、rootでなければ開けない(2026-11-08、RTX 3050のマシンで実際に。rootで流したddでは鳴るのにmpvでは鳴らなかった)。pw groupmod audio -m ユーザー名 の後、Xfceからログアウトして入り直す。スクリプトは入れておく。
  • 音が出なければ、まず cat /dev/sndstat で音声の出力先(pcm0:・pcm1:…)と、どれが既定(default)かを見る。GPUのHDMIの音声(NVIDIA・AMD)と、マザーボードの出力(Realtek等のanalog)のどちらが既定かを見る。モニターのスピーカーから出すならHDMIの方で、NVIDIAはpcm0〜pcm2のようにいくつも出るが、モニターがつながっているのは1つだけ(RTX 3050ではpcm2)。どれかは、mpv --audio-device=oss//dev/dspN ファイル(NはpcmNの番号)を順に試して確かめる(mpvの再生中のメニューでも選べる)。
  • 決まったら、sysctl hw.snd.default_unit=N で既定にし、/etc/sysctl.conf にhw.snd.default_unit=Nを足して再起動後も残す。出力先を指定しないアプリが開く/dev/dspがこれを指すので、mpvもmplayerも(usilicのLAUNCHから開いた時も)そのまま鳴る(2026-11-08、RTX 3050のマシンでN=2)。cat /dev/sndstat でpcmN:の行にdefaultが付いていれば切り替わっている。
  • マザーボードの内蔵オーディオで聴くなら、cat /dev/sndstat のRear(背面の緑の端子、スピーカー)かFront(前面のヘッドホン端子)の番号にする(RTX 3050のマシンではpcm3: <Realtek ALC892 (Rear Analog 7.1/2.0)>・pcm4: <Realtek ALC892 (Front Analog)>)。背面は、何も設定しなくても既定(default)に選ばれていることが多く、その時はaudioグループに入れるだけで鳴る(番号を変えるのはHDMIのモニターのスピーカーで聴く時)。前面と背面は別の出力先なので、ヘッドホンを挿しても自動では切り替わらない。ヘッドホンで聴く時は前面の番号にする。
  • 1つのアプリだけ別の出力先にするなら、mpvは ~/.config/mpv/mpv.conf にaudio-device=oss//dev/dspN、mplayerは ~/.mplayer/config にao=oss:/dev/dspN。
  • 何も出てこない(No devices installed)なら、ドライバが読み込まれていない。kldload snd_hda(USBなら kldload snd_uaudio)。
  • 音量は mixer で見られる(mixer vol.volume=0.8 等)。dsbmixer(実機のXfceの端末で dsbmixer。sshからは DISPLAY=:0 dsbmixer)は装置ごとのタブで音量を見られる。既定の装置の切り換えはrootが要り、dsbmixerからは変わらないことがあるので、その時は sudo sysctl hw.snd.default_unit=N。
  • パッケージのmpvはOSSにだけ出す(mpv --ao=help にpulseが無い、2026-11-13)。そのため、Xfceのパネルの音量のプラグインやpavucontrolでPulseAudioの出力先を切り換えても、mpvの音は付いてこない(pavucontrolの「再生」タブにmpvが出ない)。mpvの出力先は、上のhw.snd.default_unit(またはaudio-device=oss//dev/dspN)で決める。PulseAudioは、PulseAudioに出すアプリ(Xfceのシステム音等)の出力先だけを決める。パネルのアイコンの赤い斜線(消音)はPulseAudioの既定の出力先のもので、mpvの音とは関係ない。PulseAudioはFreeBSDの全部の/dev/dspNを出力先として並べる(pactl list short sinks のoss_output.dspN)。pactlのたびに出る「caps.c: Normally all extra capabilities would be dropped now…」は、FreeBSDにLinuxのcapabilitiesが無いという警告で、無視してよい。
  • i5-4570S(Haswell)のiGPUでは、HDMIから音が出なかった(2026-11-13、映像は出る)。mpv --audio-device=oss//dev/dsp0 (pcm0: <Intel Haswell (HDMI/DP 8ch)>)は、音が進まないので映像も止まる。sysctl dev.hdaa.0 に出口(pin)がnid3の1つしか無く、dmesg にモニターのELDも出ない(Linuxは起動の時にHaswellの音の部品へ全部の出口を見せる命令を送り、i915がモニターの接続を伝えるので、同じマシンのDebianではHDMIで鳴った)。試したのはこの1台だけ。このマシンでは背面(pcm1: Rear Analog)か前面(pcm2: Front Analog)で聴き、hw.snd.default_unitをそれにする(HDMIの番号にするとmpv・mplayerが止まる)。ディスクを付け替えたら、/etc/sysctl.confのhw.snd.default_unitも新しいマシンの番号に直す(RTX 3050のマシンの2はHDMI、i5-4570Sでは前面)。

パッケージとOSの更新(2026-11-08)

  • スクリプト(または手の手順)でportsからビルドしたものはpkg lockしてあるので、pkg upgrade で上がらない(Intelのdrm-612-kmod、AMDのファームウェア(RX580ならgpu-firmware-amd-kmod-polaris10)、NVIDIAのnvidia-kmodとnvidia-driver、sdl2)。それ以外は普通に pkg upgrade してよい。ロックしたものは pkg lock -l で一覧できる。
  • pkg upgrade で「Newer FreeBSD version for package」と聞かれたらy(カーネルのモジュール以外は、この程度のずれなら動く)。
  • pkg upgrade が「is locked and may not be modified」で止まったら、ほかのパッケージがロックしたものの新しい版を要している(例: sdl2_ttfが新しいsdl2を要する)。そのパッケージを pkg unlock -y し、ports(cd /usr/ports && git pull)からビルドし直してロックする。NVIDIAはnvidia-kmodとnvidia-driverを必ず両方同じ版で(片方だけだとXがNVRM: API mismatchで起動しない、2026-11-08、RTX 3050で実際に)。
  • OS(カーネル)を新しいスナップショットに上げた時は、ロックしたカーネルのモジュールが古いカーネル向けのままで読み込めなくなる。/usr/srcとportsも新しくしてから、ロックしたものを pkg unlock -y し、スクリプトをもう一度実行する(ロックが外れていて読み込めないものをビルドし直す)。その時のpkgの版がカーネルと合っていれば、ビルドせずにpkgの版に戻してもよい。
  • ZFSで入れたなら、大きな更新の前に bectl create before-upgrade しておくと、起動しなくなっても起動メニューの「Boot Environments」から更新前に戻せる。

    distは、strip済みのusilic.exe・usilic-c.exe・SDL2.dll・SDL2_ttf.dllと、lib/usilic/(usilicrc・HELP・HELP.notes、~/.local/lib/usilic/HELP.epubがあればそれも)をまとめる。

Windowsで使う

  1. usilic-win64.zipを好きな所(例えばC:\Users\<名前>\usilic\)に展開する。
  2. usilic.exeをダブルクリックするか、コマンドプロンプトからusilic.exe [ディレクトリ|ファイル]。引数が無ければカレントディレクトリ(ダブルクリックならexeの場所)の(ls)。端末の中で使うならusilic-c.exe (usilic.exe -cはそれを案内して終わる)。^Zのサスペンド、CUIの^J^F等の-g専用の機能は使えない。
  3. 設定・履歴は%USERPROFILE%\.usilic\(HOMEが無ければUSERPROFILEを使う)、HELP・既定のusilicrcはexeの隣のlib\usilic\。フォントはC:\Windows\FontsのMSゴシック(無ければConsolas)、和文のゴシック体はメイリオ、明朝体は游明朝。
  4. 窓が出ない時はメッセージボックスで理由を出す(フォントが無い等)。SDL2.dllが無いとWindows自身が起動前に知らせる。

macOS: Finderからアイコンクリックで起動する(.appバンドル)

cd usilic/src/cpp
make app        # build/usilic.app ができる
open build/usilic.app   # 動作確認(実際にウィンドウが開く)

usilicは引数無し起動だとmacOSでは元々GUIモード(SDL2の独立ウィンドウ、ターミナル不要)がデフォルトになる設計になっているため、make usilicが作るbuild/usilicをそのまま.appバンドルへ包むだけで、Finderからのダブルクリック起動に対応できる(2026-08-24、docs/CHANGES.md項目421)。GUI側の追加実装は不要だった。

build/usilic.appをFinderで/ApplicationsやDockへドラッグすれば、以後は通常のアプリと同じ感覚でアイコンクリック起動できる。ターミナルからのU起動(-cでCUIも選択可)は影響を受けない。

署名について: make appは末尾で.appバンドル全体をad-hoc署名し直す(codesign --force --deep -s -、単体実行ファイル用の署名をバンドル構造にそのまま流用するとspctl -aがrejectedになるため必須)。有償のDeveloper ID証明書による署名・公証(notarization)は行っていないため、他のMacへコピーした場合やcom.apple.quarantine属性が付いた場合は、初回起動時にGatekeeperの確認(右クリック→「開く」)が必要になることがある。ローカルでビルドしたものをそのまま使う分にはこの確認は出ない(quarantine属性が付かないため)。

アイコンは未設定(Finderの汎用実行ファイルアイコンのまま)。.icnsをsrc/cpp/packaging/へ追加しInfo.plistのCFBundleIconFileを設定すれば、以後のmake appで自動的に反映される。

やりたいことGitHubのアカウント鍵・認証
公開リポジトリをhttps://でcloneする・更新を取り込む不要不要
自分の変更を自分のGitHubに置く(fork→push)必要SSHの鍵、またはgh auth login
作者に変更を送る(Pull Request)・不具合を報告する(Issue)必要(ブラウザでサインイン)
  • SSHの鍵はアカウントに登録するもので、https://github.com/settings/keysはサインインしないと開けない。
  • 鍵は使うマシンでssh-keygen -t ed25519で作り、~/.ssh/id_ed25519.pubの1行を上のページのNew SSH keyに貼る。そのマシンにまだブラウザが無ければ(FreeBSDを入れた直後等)、sshでつないだ別のマシンの端末でこの1行をコピーし、そちらのブラウザ(サインイン済み)で登録してもよい。
  • gh auth login(GitHub CLI)なら鍵を作らずに済み、表示されたコードを別のマシンのブラウザで入力しても通る。
  • 鍵とURLの組み合わせに注意: SSHの鍵が使われるのはgit@github.com:haa15030/usilic.gitの形のURLだけ。https://github.com/...で非公開のリポジトリをclone(や自分のforkへpush)するとUsername for 'https://github.com':と聞かれ、パスワードの欄にはGitHubのパスワードではなくトークンを入れる(パスワードは受け付けない)。鍵を登録したなら、URLをgit@github.com:の形にすればトークンは要らない(2026-11-01、FreeBSDで鍵を登録した後にhttps://でcloneしてこれに当たった。既にcloneしたものはgit remote set-url origin git@github.com:…で切り替えられる)。
  • トークンの作り方(https://のまま使う場合): GitHubにサインイン→右上のアイコン→Settings→ (左の一番下)Developer settings→Personal access tokens→Fine-grained tokens→Generate new token。Token name(何でもよい)、Expiration(有効期限)、Repository accessはOnly select repositoriesでusilicを選び、Permissions→Repository permissionsのContentsをRead-only(cloneだけ)かRead and write(pushもする)に。Generate tokenで表示されるgithub_pat_…はその時しか表示されないのでコピーしておく。cloneのUsername:に自分のアカウント名、Password:にこのトークンを貼る。毎回聞かれないようにするにはgit config --global credential.helper store(~/.git-credentialsに平文で保存される。気になるならcacheで一定時間だけ覚えさせる)。gh auth loginを済ませておけば、ghがこの役目も引き受ける。
  • 手順: GitHubで作者のリポジトリをFork → git remote add mine git@github.com:<自分>/usilic.git → git push mine my-fix → GitHubのページからPull Request。
  • 作者以外が1つのリポジトリだけを読む機械用には、リポジトリの所有者が登録するDeploy key(Settings→Deploy keys)もある(非公開の間に、作者が自分の別マシンへ取ってくる時等)。
